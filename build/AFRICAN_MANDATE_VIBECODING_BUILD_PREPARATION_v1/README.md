# African Mandate — Vibecoding Build Preparation Package v1
**Prepared:** 2026-10-08  
**Status:** Implementation-preparation package; proposed governance documents, **not** a compiled game, approved architecture amendment, or proof of test execution.

## Purpose
Translate the existing project specifications into bounded, testable coding-agent assignments without introducing new game rules. The package is a **repository scaffold** to merge into the real code repository after owner review; do not confuse this package with the existing repository.

## Contents and order
1. `BUILD_CONSTITUTION.md` — precedence, immutable rules, approval policy and decision status.
2. `EXECUTABLE_CONTRACT_INVENTORY.md` — serializable schema, registries, compiler artifacts, source dependencies and test contracts.
3. `AGENTS.md` — instructions for AI coding agents and code-review discipline.
4. `REPOSITORY_BOOTSTRAP.md` — proposed monorepo layout, scripts, CI and ownership boundaries.
5. `IMPLEMENTATION_ROADMAP.md` — dependency-ordered tasks and phase exits.
6. `TASK_CONTRACT_TEMPLATE.md` and `task_contracts/` — reusable and first-wave executable work orders.
7. `ACCEPTANCE_MATRIX.md` — traceability and release gates.
8. `OPEN_DECISIONS.md` — blockers, owner-required approvals and stale-spec reconciliation.
9. `adr/ADR-0001-verified-leaderboard-boundary-PROPOSED.md` — draft amendment, **not an approval**.

## Safe start
Start with specification freeze and repository toolchain, then Zod schemas, deterministic primitives and a synthetic test-only vertical slice. Historical data or unapproved coefficients never become production truth just because schemas require values.
